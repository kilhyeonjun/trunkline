# Trunkline v0.1.3

This patch release makes usage reporting read the sources that are actually
fresh. Both providers could report nothing on a working install while current
data sat on disk.

## Highlights

- `trunkline usage` reads the live `~/.codex/auth.json` for the active account
  instead of its store snapshot. The Codex CLI rotates the live file in place,
  and snapshot absorption only runs on a switch, so a single-account or locked
  setup never absorbed a rotated token. The snapshot aged until the usage
  endpoint answered `usage HTTP 401`, while the stale token's own expiry was
  still in the future and did not trip the local expiry gate.
- The active account is decided by matching the live identity against the
  snapshots, so a live file that matches nothing falls back to snapshots rather
  than guessing a destination. The plan label is read from the same file as the
  usage row, so the two cannot disagree.
- `usage.py` is unchanged and still holds no token-rotation capability.
- Claude status now reads `~/.trunkline/claude_usage_live.json` before the
  `cachedUsageUtilization` gate. A Claude Code build that stops writing that key
  made the reader answer `cache_missing` and discard a statusline bridge file
  that was seconds old.
- `cache_missing` is now reported only when both sources are missing. A live
  record without an `at` timestamp cannot be compared for freshness, so it still
  counts as absent instead of reporting an all-null status as ok.
- The menu bar app is unchanged; it consumes `usage --json` and picks this up
  the next time its menu opens.

## Install

Requires Python 3.11 or later:

```bash
pipx install https://github.com/kilhyeonjun/trunkline/releases/download/v0.1.3/trunkline-0.1.3-py3-none-any.whl
trunkline --help
```

Verify `trunkline-0.1.3-py3-none-any.whl` against its published SHA-256 file
before installation.

## Update and rollback

Before updating, back up `~/.codex` and `~/.trunkline`. To roll back, download
and verify the previously released wheel, then install that local file:

```bash
curl -fL -o trunkline-0.1.2-py3-none-any.whl https://github.com/kilhyeonjun/trunkline/releases/download/v0.1.2/trunkline-0.1.2-py3-none-any.whl
echo '676811f7ac1521848a53c5fd89a834b66ca7bc5489aa85ea7f4472cd45de0936  trunkline-0.1.2-py3-none-any.whl' | shasum -a 256 -c -
pipx install --force trunkline-0.1.2-py3-none-any.whl
```

Rollback does not delete Trunkline state or snapshots. Confirm `trunkline
health` before using `auto` again.

## Known limitations

- This is alpha software. Codex is the only account-switching provider.
- Rolling back reintroduces the `usage HTTP 401` on a locked or single-account
  setup whose snapshot has aged behind the live file.
- A snapshot that is not the active account is still only refreshed by a switch,
  so its usage row can report an expired or rejected token.
- The menu bar app requires macOS 14 or later and Swift 6/Xcode to build.
- The app is ad-hoc signed and not notarized; there is no PyPI, Homebrew, or
  automatic-update channel.
