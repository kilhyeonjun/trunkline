# Trunkline v0.1.2

This patch release makes Claude status reporting survive a missing credentials
file, which is the normal state on macOS.

## Highlights

- `trunkline status` and `trunkline usage` now report Claude usage even when
  `~/.claude/.credentials.json` does not exist. macOS Claude Code keeps its
  OAuth material in the Keychain, so the file is absent there and the usage
  already present in `~/.claude.json` was being discarded along with it.
- A missing, corrupt, or wrongly typed credentials payload degrades to an
  unknown login expiry instead of failing the whole read. No re-login warning is
  invented for an unknown expiry.
- A non-dict credentials payload previously raised `AttributeError`; it is now
  handled.
- Reading the Keychain remains forbidden, and the daemon still adds no network,
  rotation, or background inference.

## Install

Requires Python 3.11 or later:

```bash
pipx install https://github.com/kilhyeonjun/trunkline/releases/download/v0.1.2/trunkline-0.1.2-py3-none-any.whl
trunkline --help
```

Verify `trunkline-0.1.2-py3-none-any.whl` against its published SHA-256 file
before installation.

## Update and rollback

Before updating, back up `~/.codex` and `~/.trunkline`. To roll back, download
and verify the previously released wheel, then install that local file:

```bash
curl -fL -o trunkline-0.1.1-py3-none-any.whl https://github.com/kilhyeonjun/trunkline/releases/download/v0.1.1/trunkline-0.1.1-py3-none-any.whl
echo '73c8b6b34cde39463c63422a81a61ba61bf1d24d3a5997e4e2137b28b96c439d  trunkline-0.1.1-py3-none-any.whl' | shasum -a 256 -c -
pipx install --force trunkline-0.1.1-py3-none-any.whl
```

Rollback does not delete Trunkline state or snapshots. Confirm `trunkline
health` before using `auto` again.

## Known limitations

- This is alpha software. Codex is the only account-switching provider.
- With the credentials file absent the login expiry is unknown, so the daemon
  reports `login_ok: true` for that case. It means "no known expiry problem",
  not a verified session.
- The menu bar app requires macOS 14 or later and Swift 6/Xcode to build.
- The app is ad-hoc signed and not notarized; there is no PyPI, Homebrew, or
  automatic-update channel.
